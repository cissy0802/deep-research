# G11-V 逐字席判决(SCWarn、Walmart AIDR、SCELM、AnoFusion 复现)

## CHANGE:C28 SCWarn — CORRECTED(口径降级)
- 两句引语与摘要逐字一致。摘要原文是 "performs not well to handle heterogeneous multi-source data",论断转述为「难以处理」,可以接受。
- 50.4% 只有摘要层的依据，样本是 "large-scale real-world data from a large commercial bank";分母和时间窗摘要没有给，论断已经如实注明。
- **修正:**摘要原文是 "An extensive study on two datasets with various bad software changes demonstrates our approach significantly outperforms all the compared approaches, achieving 0.95 F1-score on average and reducing MTTD ... by 20.4%∼60.7%"。摘要没有说明 MTTD 降幅是相对哪个对象。「与基线方法比较、不是线上前后对比」只是合理推断，正文未核。成文写「MTTD 降幅的比较对象摘要未写明(推断为对比算法)」。
- 作者为 Nengwen Zhao、Kaixin Sui(BizSeer)、Dan Pei(清华)等。
- 证据分级：单源已核(仅摘要层，作者自评)。

## DETECT:D22 Walmart AIDR — CORRECTED
- 两句引语都逐字存在。PDF 断行把 "regression-based" 排成 "regressionbased",不影响核对。3000+ 模型、25+ 团队、3 个月、27/48、56%、7.2 分钟、91% 均存在于原文。
- **修正 1(分母):**63% 不是 Walmart 全部重大事故的覆盖率。正文说 "These models alerted early for 37 major incidents"。四个案例客户的检出数加起来是 4+3+3+27 = 37,对应分母 4+3+3+48 = 58,37/58 = 63.8%。所以 63% 只对应 **4 个案例客户共 58 起重大事故**,其中 48 起来自 Operations 一个团队。这是推算，但吻合得很精确。
- **修正 2(原文内部不一致):**摘要写 "more than 25 ... teams",正文写 "around 30 application, internal platforms, operations teams"。噪声降幅也对不上：正文说 Pricing & Delivery 为 "91% noise reduction compared to non-AIDR alerts",Table 3 对应列却是 94%;Operations 在表和正文中都是 91%。论断把 91% 只归给 Operations,与 Table 3 一致，但应注明原文自身有矛盾。
- 原文没有基线 MTTD,论断的说法成立。
- XGBoost 与 ARIMA 的数字来自 Table 1,是**单一 POS 流量指标、90 天验证**的结果，不是平台整体表现，成文必须带上这个限定。
- 证据分级：单源已核(workshop 论文,Walmart 自评)。

## DETECT:D23 SCWarn 自报与 AnoFusion 复现 — CORRECTED(上下文改变含义)
- SCWarn 摘要逐字一致。AnoFusion 的 Table 3 是 PDF 按列交错排版，拆开后 SCWarn 在 D1 为 P/R/F1 = 0.547/0.425/0.447,在 D2 为 0.633/0.891/0.734,数字一致。论断里的引语「行」是调研员按行重排的，不是逐字原样。
- **修正 1(任务不同):**AnoFusion 评测的是「微服务**实例故障检测**」(instance failure detection),不是坏变更识别。D1 是 GAIA 数据集(CloudWise);D2 来自 "a large-scale microservice system operated by a commercial bank",故障由人工注入。SCWarn 不使用 trace,AnoFusion 明说这是它在 D1 上表现差的原因。所以这组数字只能说明 **SCWarn 换任务、换数据后 F1 掉到 0.45–0.73**,不能直接得出「自有数据上的坏变更检测数字不迁移」。
- **修正 2(利益关系):**AnoFusion 和 SCWarn 有共同作者 Dan Pei(清华),属于同一学术圈，不是独立的竞品团队。不过 AnoFusion 是新方法作者，有压低基线分数的动机，「有利益」这一点成立。AnoFusion 写的是 "we use grid-search to set their parameters best for accuracy"。
- 证据分级：单源已核(复现方单一，任务不同)。

## CANARY:C28 SCELM — CORRECTED(补严重警示)
- 三段引语都逐字存在。原文的破折号 "D1—sampling" 在归一化后匹配。
- 「抽 10% 只有 2 个案例」原文出现在 **FT(故障分类)任务的历史经验比例**分析中，不是 ECD 检测任务。D1 约 20 例是推断，可以保留，但要注明出处语境。
- **补充警示 1(稿件完成度):**这份预印本的实验设置一节只有提纲，原文为 "• Datasets: yunzhanghu, kontrast, bytedance • Baseline Approach • Evaluation Metric • Deployment: environment",没有数据集规模、基线配置和指标定义。首页还残留 ACM 模板的图注占位 "Fig. 1. Seattle Mariners at Spring Training, 2010."。D1/D2/D3 与三个数据集名称的对应关系，原文也没有明确写出。这些 F1 数字**不可承重**。

- 证据分级：未验证(数字可回溯，但稿件缺实验设置，等同不可复核)。

## 组级判决:CORRECTED(HOLDS 1 / CORRECTED 4 / REFUTED 0)

### 锁定口径
1. Walmart 的 63% = 4 个案例客户共 58 起重大事故中检出 37 起(其中 Operations 一个团队占 48 起、检出 27 起),不是全 Walmart 的覆盖率。原文内部团队数(25+ 与约 30)和噪声降幅(91% 与 94%)前后不一致。XGBoost 和 ARIMA 的数字只对应单一指标。
2. SCWarn 的 0.95 和 20.4–60.7% 只有摘要层依据，正文未读;MTTD 的比较对象摘要未写明。
3. AnoFusion 复现的是「实例故障检测」任务，不是坏变更检测。复现方与 SCWarn 有共同作者(Dan Pei)。只能说「换任务、换数据后 F1 为 0.45/0.73」。
4. SCELM 是实验设置缺失的草稿态预印本，F1 1.000/0.942/0.925 不承重。90% 是 OCE 反馈的 time to resolution,不是检测速度。
