# G14-V 逐字席判决(AI SRE 厂商宣称、「LLM 不进检测段」)

核验方法：用 curl 下载各页面 HTML,去掉标签并归一化后做子串比对。日期取页面 JSON-LD 中的 datePublished。对于用 JS 渲染的内容(例如 Cleric 的脚注),curl 拿不到，不能核实。

## RCA:L19 AWS DevOps Agent GA — HOLDS
- 两句引语逐字存在(破折号经过归一化)。页面元数据中的日期是 2026-03-30 和 2026-03-31。
- 那个 20–30 分钟的案例是一次「黑客松期间」的事故。原文 "the 1-2 hours it would have taken manually" 没有出现 "estimate" 这个词，但这是假设性的对比，论断写「估计」，意思没有偏。
- 证据分级：厂商口径。

## RCA:L20 「检测仍由传统监控完成」— CORRECTED(过度概括)
- Granola 的引语和 PagerDuty 的集成说明都逐字存在。后者原文是 "PagerDuty : Native integration ...",冒号前有空格。
- **修正 1:** 同一页面上就有反例。L19 引用的那个案例原文写道："nothing significant showed up in monitoring ... the team pasted the issue into AWS DevOps Agent"。也就是说，这次调查是人发现问题后**手动**发起的，并非由告警触发。所以应写成「调查的入口是告警或人工发起，在 GA 帖子里，LLM 都不负责首次发现异常」，不能写成「均由告警自动触发」。
- **修正 2:**「Datadog 文档同样以 monitor alert 为入口」这一句没有给出 Datadog 文档的 URL。可以用 Datadog 博客原文代替:"Bits Investigation is our new agent that automatically investigates incidents and monitor alerts"(datadoghq.com/blog/building-bits-ai-sre)。
- 「TTD 不变」是推断，原文没有给出任何 TTD 数据。
- 证据分级：厂商口径。方向成立，属推断。

## RCA:L26 Grafana 3.5x — CORRECTED(补关键上下文)

## 组级判决:CORRECTED(HOLDS 5 / CORRECTED 6 / REFUTED 0)

### 锁定口径
1. AWS 的 75% / 80% / 94% 都是「预览期客户与伙伴报告」，带 "up to" 限定，没有分母。调查入口包括告警触发和人工发起(同页就有人工发起的反例)。LLM 不负责首次发现异常，TTD 的说法属推断。
2. Datadog:准确率没有数字;速度方面有两个数字：约 2 倍(3–4 分钟),以及 time to resolution "up to 95%"。
3. Traversal 两篇文章都有日期:2026-02-12 和 2026-08-19。
4. Resolve:MTTR ~60% 大于调查时间 ~30%,说明 MTTR 降幅不能归到定位段。
5. Cleric 脚注和统计窗口未核实，不引用。
6. Grafana:AI 与人同时开始排查，由告警发起;这次事故本身是一次通过了 staging、CI 和代码评审的坏部署。
7. Google:2026-04-10 起，需要有 Premium Support 合同或经客户团队申请才能使用。
