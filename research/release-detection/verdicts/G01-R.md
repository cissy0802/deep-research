## 逐条判决

### CHANGE:C01 — HOLDS|单源已核(官方一手、无口径)
原句都在。补一条供对照:Workbook 把 user behavior change 单列为 9%,书中定性句却把「new type of user traffic」算作 change,所以「change」的宽窄口径会让数字落在 68%(binary+config)到 77%(再加 user behavior)之间。

### CHANGE:C02 — CORRECTED|单源已核(厂商内部数据)
Table C-1 八行相加恰好 100%(37+31+9+6+5+5+5+2),而 Table C-2 五行加起来只有 87.97%。可见 C-1 的百分比要么是在前八类内部归一化的,要么前八类覆盖了全部;原文没说这是「全部 outage」的分母。
修正表述:「Google 从 2010–2017 年数千份 postmortem 中抽样,统计前八类触发因素;在这八类的占比里,binary push 37% 加 configuration push 31%,合计 68%。」不要写成「68% 的 outage 由推送触发」而不加限定。还要注意:有 postmortem 的事故才进样本,所以有选择偏差。

### CHANGE:C08 — HOLDS(补充反向口径)|单源已核(同行评审)
原表数字一致(UPGRADE 54 起/16%,在 18 个服务中出现)。反向补充:597 起里 355 起(59%)根因未知,所以 UPGRADE 只占**全部**事故约 9%(54/597),UPGRADE 加 CONFIG 约 15%(88/597)。公开报道口径下,「变更类」事故的占比远低于 70%。这是对 70% 叙事最直接的反向数据,但它的样本是公开报道,不能和内部 postmortem 直接比。

### CHANGE:C09 — HOLDS|单源已核(同行评审,自家数据)
原句与 42/36/22 都一致。

### CHANGE:C19 — HOLDS|多源证实(经典文本)
没有需要修正的地方。

### CHANGE:C26 — CORRECTED|厂商口径
23%、85%(仅限人为错误类 outage)、三分之二(九年的公开 outage)都已核实。「change management/misconfigurations」只是 Uptime 的推测(原文是 likely),不是测出来的结论。**54% 电力**在新闻稿里没有,新闻稿只写「Power remains the leading cause of impactful outages」。成文时去掉 54%,或者标为「付费报告,媒体转述,未核」。

### CHANGE:C28 — HOLDS|单源已核(仅摘要)
50.4% 是一家银行内部的数据;MTTD 降幅是在离线数据集上与基线方法比出来的。不要和 Google 的 70% 并列成「行业共识区间」。

### CHANGE:C29 — CORRECTED|单源已核
70% 的引文属实(引 [7] 即 SRE 书)。但「基线规则召回 56%」写错了。原文是**加权召回 wR = 0.56**(按类别样本量加权平均,负类占绝大多数,所以 wR 主要反映负类),同时 precision 0.04、AUC 0.55(作者自己说「近乎无判别能力」)。最佳模型 LightGBM 的 wR 是 0.91,但 precision 只有 0.02。
另外,这是**部署前**的变更风险预测,不是上线后的检测,不能当作发布后检测的证据。

### CANARY:C11 — HOLDS|单源已核
三句原文都在。Workbook 自己列的 canary 局限也可以引用:流量太少时信号不具代表性、性能缺陷只在高负载下出现、要考虑观察窗口长度等。

## 组级判决:CORRECTED(HOLDS 6 / CORRECTED 3 / REFUTED 0)

## 成文时必须使用的锁定口径
1. 「约 70%」只能写成「Google SRE 书里的经验断言,原文未给数据口径」。最接近它的可追溯数据是:2010–2017 年 postmortem 抽样中,前八类触发因素里 binary 加 config 推送占 68%;是触发因素,不是根因,而且八类相加恰好 100%。
2. 公开报道口径(SoCC'16)下,UPGRADE 占已知根因标签的 16%,占全部 597 起事故约 9%;UPGRADE 加 CONFIG 占全部约 15%。
3. 单个企业的数据:Facebook 16% 与配置相关(3 个月);某银行 50.4% 由坏变更引起。这些不是行业基准。
4. Uptime 不写 54% 电力;它的「change management」归因只是推测。
5. ING 论文的 56% 必须写成「加权召回」,并且同时给出 precision 0.04 和 AUC 0.55。
