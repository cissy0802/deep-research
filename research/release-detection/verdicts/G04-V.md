## 逐条

**C1 HOLDS。** 各案原文:
- CF-2019:"The SOP allowed a non-emergency rule change to go globally into production without a staged rollout."
- CF-12-05:"does not perform gradual rollouts"
- GCP:"replicated globally within seconds"
- CF-11-18:"rapidly propagated across the network",fail-small 文中进一步说明 "in both incidents this caused a breaking change to propagate to the entire network in seconds rather than passing through gates"

CrowdStrike PIR 只明说 sensor 走 "staged sensor rollout",对 Rapid Response Content 的表述是整改项("Implement a staggered deployment strategy for Rapid Response Content ... starting with a canary deployment")。「当时不分阶段」是由整改反推的,成文应写「整改承诺暗示事发时未分阶段」;国会证词未重核。

**C2 CORRECTED。** 附的代表引语(CF-12-05)对比的是**两个配置系统**,不是「代码 vs 配置」:"This first change was being rolled out using our gradual deployment system ... This second change ... was implemented using our global configuration system"。两次变更都是配置,所以 CF-12 不能作为「代码渐进、配置不渐进」的原文证据。真正直说代码与配置不对称的来源有:
- Cloudflare fail-small:"For each new binary release, the deployment must successfully complete multiple gates ... We have not applied that methodology to configuration changes."
- GCP:代码 "region by region rollout",数据 "replicated globally within seconds"
- AFD 博客:代码 SDP 约 2–3 周,客户配置 5–10 分钟
- CrowdStrike:sensor staged,内容不分阶段(推断)

锁定表述:「4 个厂商(Cloudflare、Google、Microsoft、CrowdStrike)的官方材料明说或暗示代码与配置/数据的发布节奏不对称」,引语改用 fail-small 那句。

**C7 CORRECTED。** AFD-29 引语逐字命中。延迟数字逐个核对:

## 成文时必须使用的锁定口径
1. 「代码渐进、配置秒级全球」的直接原文用 Cloudflare fail-small:"We have not applied that methodology to configuration changes",配合 AFD 的「代码 2–3 周 / 安全数据 >12 小时 bake / 客户配置 5–10 分钟」。不要拿 CF-12-05 那句当「代码 vs 配置」的证据,那是两个配置系统之间的对比。
2. 潜伏期只写已核的三个:GCP 14 天、Fastly 27 天、AFD-29 约 5 分钟(异步)。删去「15 天」和「6 周」。
3. canary 结构性盲区有三种已核形态:(a) 故障路径需要另一条变更才触发(GCP);(b) 异步、延迟发作,能通过健康门控并污染 LKG(AFD-29);(c) 人工覆盖绕过保护(AFD-09)。
4. CrowdStrike「事发时内容不分阶段」由 RCA 发现(Finding 6)与整改项推断得出,原文未直说。
5. Cloudflare Snapstone 的效果和 AFD 的「<10 分钟恢复」都是厂商口径(反事实或路线图),不是实测。
