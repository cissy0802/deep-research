## CHANGE:C02 — CORRECTED(单源已核)
- 数值逐项核到:Table C-1「Top eight outage triggers, 2010–2017」,binary push 37%、configuration push 31%、user behavior change 9%、processing pipeline 6%、service provider change 5%、performance decay 5%、capacity management 5%、hardware 2%;C-2 root cause Software 41.35% 等五项。
- **修正 1(分母)**:Table C-1 八项相加恰为 100%(37+31+9+6+5+5+5+2=100),说明百分比是**在 top-8 触发类别内部归一**的份额,而不是「占全部抽样 postmortem 的比例」。若有 top-8 之外的触发类别(表名为 top eight,暗示存在其他),则 binary+config 占全部 postmortem 的真实比例 ≤68%。成文应写「在前八类触发因素中,binary push 与 config push 合计占 68%」。C-2 五项合计 88.0%,是部分列举,不可加总推断其余。
- **修正 2(推论)**:「这是 70% 说法最接近的可追溯数据」只能作为研究者推断:SRE 书(2016)未引用任何数据,Workbook(2018)也未声称 70% 出自 C-1。成文写「与 70% 量级相近,但书中并未说二者同源」。
- 抽样口径(sample of thousands of postmortems over the last seven years;trigger≠root cause)核对无误。
- 分级:单源已核(厂商内部数据)。

## 成文必须使用的锁定口径
1. 「70%」= SRE 书经验断言,无数据;change 含新类型用户流量。不可写成「70% 事故由发布引起」。
2. Google 37%+31%=68% = **top-8 触发因素内部归一的份额**(2010–2017,数千份 postmortem 抽样,trigger 非 root cause);占全部 postmortem 的比例 ≤68%,未知。不可称其为 70% 的出处。
3. SoCC'16 UPGRADE 16% = 已知根因**标签**中的占比(340 个标签);相当于全部 597 起的 9%;59.5% 事故根因未知;样本为公开报道。
4. Facebook 16% = 3 个月高影响事故中「与配置管理相关」,非「配置变更触发」。
5. 各家「变更占比」(Google 68%/top-8 触发、银行 50.4%/坏变更、SoCC 16%/升级标签、FB 16%/配置相关、Uptime 23%/IT 网络类)**分母、定义、样本全不同**,不得并列成一个比例区间或趋势。
6. SCWarn MTTD 降幅 = 离线数据集上对比基线,作者含 AIOps 厂商 BizSeer。
7. ING 56% = weighted recall,precision 0.04;属部署前预测。
8. Uptime 54% 电力未在一手核到,不用。
