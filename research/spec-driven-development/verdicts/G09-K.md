# G09 — Lens K(口径)

**组判定:修正**(六条引语与限定语在 martinfowler.com 原页(2025-10-15)上全部定位,无数字被证伪;但 C20/C23 的 spec 分型标签需修正,且整组只能作 n=1 定性案例,不能作 SDD 主张 1 的效果证据)

核验底稿:直接抓取 https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html(HTTP 200,页面日期「15 October 2025」),去标签后逐句 grep。Round 1 的三份剪藏与原页一致,本组 6 条全部可**升级为一手直读**(原 confidence 已是 verbatim-checked,经剪藏;现为原页)。

- **C19 HOLDS(带限定)**:原页段落「When I asked Kiro to fix a small bug (it was the same one I used in the past to try Codex)… 4 “user stories” with a total of 16 acceptance criteria」逐字在。口径:n=1 次运行、2025-10 的 Kiro(GA 前)、T1 需求文档;「4 个 user story / 16 条验收标准」是**产物规模**口径,不是时间、token 或缺陷口径——只能支持「流程规模与问题规模失配」,不能换算成成本倍数。
- **C20 修正(分型)**:「3-5 point story」原文在(「a feature that would be a 3-5 point story on one of my past teams」),「spec-kit created a LOT of markdown files…verbose and tedious to review」逐字在。修正前 T2 → 修正后 **T1+T2 混合**(spec-kit 产物含 spec.md 需求型 + plan/tasks 计划型;作者批评对象是整批文件,未区分)。无文件数/行数/审阅时间——禁止写成「X 行/X 小时」。同段还有「In Kiro it was a little easier, as you only get 3 files」:同一作者对两工具的相对判断,可用但仍是 n=1。
- **C21 HOLDS**:逐字在。性质为作者偏好(评论),不得写成「审 spec 比审代码更贵」的测量结论。可与 G11 C34(Garg:带 spec 审阅 48.4 vs 26.7 分钟)并列,但两者口径不同(后者是对照代码审阅时把 spec 当基线,不是审 spec 本身)。
- **C22 HOLDS**:逐字在;同段还有「I frequently saw the agent ultimately not follow all the instructions」与「go way overboard because it was too eagerly following instructions (e.g. one of the constitution articles)」——均为未计数的「frequently」,只能写「作者多次观察到」,不能写频率。
- **C23 修正(分型)**:引语逐字在。修正前 T3 → 修正后 **非 T3**:原页描述的 Tessl spec 是 markdown 自然语言规约 + API 段 + `@generate/@test` 标签、1:1 对应代码文件——属 T1(带接口描述)/T4(链接测试)混合,不是形式契约。把 Böckeler 的 MDD 类比算作「T3 形式规约的前科」属跨型混引。另:原页示例 spec 是用 `tessl document --code` **从现有 JS 文件反向生成**的,且作者「generated code multiple times from the same spec」观察到非确定性(未给次数/差异度)——这是主张 3(代码可再生)唯一的一手观察,方向对主张 3 不利,但 n 未知、无量化,只能定性。「MDD never took off for business applications」是亲历判断,须交 G15(Petre/Hutchinson/Whittle)的调查数据支撑,单独不得承重。
- **C24 HOLDS**:「So the general principle of spec-first is definitely valuable in many situations」与「semantically diffused… ‘spec’ basically as a synonym for ‘detailed prompt’」逐字在。这是本组最重要的口径限定:作者把 spec-first(主张 1 的轻量版)与 spec-anchored/spec-as-source(主张 2/3)分开评价——成文不得把她归为「反对 SDD」。

**利益相关**:Thoughtworks 不卖 SDD 工具,但卖 AI 辅助交付咨询;利益方向中性偏弱,写「Thoughtworks 顾问」即可。

## 成文提示
- 必须带的限定:2025-10 版本工具、单人单次试用、无计时/无 token;Kiro 当时未 GA。
- 分型:spec-kit 批评 = T1+T2;Tessl = 自然语言 spec(非 T3)。Böckeler 自己的三级分类(spec-first / spec-anchored / spec-as-source)与本期 T1–T4 是正交维度,引用时两个维度都写清,不要混。
- 注意:Böckeler 判定 spec-kit「still what I would call spec-first only」;而 Eberhardt(G10)称 spec-kit 是「purest form (spec-as-source)」——两位作者对同一工具分级相反,成文不得把两者的分级当同一口径并列。
- 禁止:「Böckeler 证明 SDD 无效」「审 spec 比审代码贵」(无测量)。
- 最强写法:「Thoughtworks 的 Böckeler 在 2025 年 10 月试用三款工具后认为 spec-first 原则『在许多情况下肯定有价值』,但批评现有工具对小问题过重、产出冗长难审、agent 并不总遵守 spec;她对 spec-as-source 的担忧是『同时继承 MDD 的僵化与 LLM 的非确定性』——这是单人试用的定性判断。」
