- **C17 HOLDS → 升级(已回一手)**:
  - Piskala 原文:"Empirical studies [5], [6], though nascent, suggest that human-refined specs significantly improve LLM-generated code quality, with controlled studies showing error reductions of up to 50%."——[5] = Griffin & Carroll, InfoQ, 2026-01;[6] = Naszcyniec, Red Hat Developer, 2025。两文全文检索:均无对照研究、实验或"50%"数字;InfoQ 仅有"in our experiments"式的经验描述(漂移类型举例),Red Hat 仅有愿景句 "Think 95% or higher accuracy in implementing specs on the first go"。"50%"按无源数字处理成立。
  - Marri 73% 复算:Table 3 "CWE Violations Detected 3 vs 11 → 73% reduction"(8/11=72.7%);同表"56% faster""75% reduction"同源于 n=1。§5.3 原文 "implementing the same banking application requirements twice … Both implementations used the same AI assistant (Claude) and the same developer";§6.6 "Small sample size (n=1 project) limits statistical power"。**口径注**:Hill 写"implementing both conditions sequentially",但 Marri 原文**未说明两次实现的先后顺序**——"sequentially"是 Hill 的补充推断(同一人两次实现必然有先后,但顺序/学习效应方向未披露);Marri 自身前后不一(§5 "a single developer" vs §6.6 "a single development team")。违规数由静态分析+人工复核,作者自承可能漏检。
- **C18 修正(指控降级)**:
  - Hill 原文(§2.2)"Eberhardt found Spec Kit roughly ten times slower than iterative development, producing thousands of lines of specification markdown that still resulted in buggy code" 逐字属实。
  - 对照 Eberhardt 原文:"The simple fact is I am a lot more productive without SDD, around ten times faster." ✓;两个增量共产出 2,577 + 2,262 行 markdown ✓("thousands")。关于 bug,Eberhardt 的小节标题是 **"It didn't result in better code or fewer bugs"**,正文 "the code quality created when following Spec Kit was just fine, but the simple and obvious bug threw me a little",而常规流程 "without any bugs in the implementation"。
  - 判定:Hill 的"still resulted in buggy code"夸大了程度(实为一个简单 bug,原论断所称 3 行修复本席未复核提交),但方向与 Eberhardt 自己的结论"没有更少的 bug"一致——修正前"Hill 转述失真" → 修正后"Hill 转述在 bug 程度上夸大,速度与 markdown 体量属实"。
  - 口径补充:"约 10 倍"可复算——SDD 两个增量 agent 33.5+23.5=57 分钟、人工审阅约 3.5+2=5.5 小时,产出约 989 行代码;常规流程 agent 8 分钟 + 审阅 15 分钟 + 功能测试 9 分钟,约 1,000 行,总时长比约 12×。但这是作者本人 n=1、同一应用的第二次实现(常规流程在后,熟悉需求),且作者坦言 2 小时 plan 审阅"might not have been needed"——是工作量自述,不是对照实验。

## 成文提示
- 必须带:Piskala 的"对照研究显示错误减少最多 50%"无可追溯来源(两条引文均无数据);Marri 的 73% = 3 vs 11 个 CWE 违规、单项目单人、作者自承 n=1。Eberhardt 的"10 倍"是单人自述体验。
