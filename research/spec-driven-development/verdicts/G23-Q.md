# G23 — Lens Q(逐字)

**组判定:修正**(四篇 arXiv 全文 PDF 都已用 pdftotext 检索核对,核心数字全部吻合,四条均升级为 verbatim;修正有三处:M17 作者对退化的归因被写弱了;M19 的「2 模型 × 3 次运行」不准确;M21 的 27/30 实为「spec 以段落形式给出」时的消融结果)

- **M17 修正 · 升级为 verbatim**:arXiv 2509.16941v2,§6.2 原文「Without the requirements and interface, both models tested (GPT-5 and Claude Opus 4.1) show significantly degraded performance.」Table 3:GPT-5 (HIGH) 25.9% → 8.40%;Claude Opus 4.1 22.7% → 8.20%。备注里的「25.9 与头条 23.3 不一致」已解:Table 5(public set,N=731)中 GPT-5 (HIGH) 为 25.9、GPT-5 (MEDIUM) 为 23.3,两个数对应不同推理档位。**修正归因**:原文并非「部分退化」归因于假阴性,论文给出的唯一解释就是验证器假阴性——「Since unit tests expect a narrow set of solutions, verifiers are prone to false negatives, resulting in lower pass rates. Our human augmentations mitigate these false negatives by constraining the agent's solution space」。所以这次消融混入了「测试期待特定 API」这一测量因素,不能直接读成「需求让 agent 更会解题」。
- **M19 修正 · 升级为 verbatim**:arXiv 2603.24284v1(ICN2,单作者)摘要「two-agent integration accuracy drops from 58% to 25% as detail is removed, while a single-agent baseline degrades more gracefully (89% to 56%)」「restoring the full specification alone recovers the single-agent ceiling (89%), while providing conflict reports adds no measurable benefit」。**修正运行次数**:Table 6 原文「Sonnet (n = 51, 1 run) vs. Haiku (n = 50, 3 runs, mean ± std)」。修正前「2 个 Claude 模型 × 3 次独立运行」→ 修正后「主实验 Sonnet 4 单次运行(51 题);Haiku 4.5 复制 3 次(50 题)」。任务出处:「We use 51 tasks from ClassEval」。
- **M21 修正 · 升级为 verbatim**:arXiv 2607.06636v1(TD Bank)摘要「we change a single line of the test-writer's prompt that controls whether it receives the spec as a checklist of rules」「Grounding the tests in the spec produces correct code +38 percentage points more often than this strong baseline on each of three Claude tiers」「Given the spec as a plain paragraph, the tester still recovers 27 of 30 bugs; asked to plan tests without the spec, it recovers only 2 of 30.」「On well-specified algorithmic problems it neither helps nor hurts.」**修正**:27/30 来自「spec 以普通段落给出」的消融(PROSE);清单形式(SPEC)是 30/30;真正的强基线(FREE+,已提示探测边界)是 18/30(Table 4)。30 个缺陷不是注入的,原文是「30 buggy drafts among the 48 core instances (8 tasks × 2 code models × 3 seeds)」,属自然产生的错误草稿。另有任务级符号检验「over 18 tasks … p = 0.002」。
- **M22 HOLDS · 升级为 verbatim(补限定)**:arXiv 2609.00568v1(天津大学,单作者;ASE '26,3 页)原文「We randomly sample 100 instances from each benchmark」「WiseSpec improves %Resolved by 2%∼29% and %Applied by 11%∼63% over the baselines」「Wilcoxon signed-rank test (α = 0.05) yields p < 2.5 × 10−4」「While Claude Code achieves a %Resolved score of 53%, WiseSpec further increases the score to 56%」(Claude-Opus-4.8,SWE-bench-Pro)。主实验模型为 DeepSeek-V3.2 和 Qwen-Plus-2025-12-01。「学生研究竞赛(SRC)」字样在 PDF 文本里没有定位到,写「ASE '26 短文」更稳。Table 1 中 29pp 对应 DeepSeek 在 SWE-Pro 上 35% vs Agentless 6%(对最弱基线);对 Claude Code 基线的增益为 2–15pp。
