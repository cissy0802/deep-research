## R1 Hill ESEM 2026
- **复现**:作者数据(commit a23d38a)+ 独立重实现,PSM 17,375 对 14.66% vs 15.24%、p=0.133 逐位一致;作者内 +1.42/+1.16pp 一致。
- **误判根因是分类器代码缺陷**(M):coverage.py 第 168 行注释称剥离 HTML 注释,代码只跳过 `>` 引用行 → PR 模板注释中的 `Fixes #1234` 被当成工单引用。按作者自述意图修正后 3,382/24,298(13.9%)spec'd PR 翻为 unspec'd(模板占位 2,382 + 连字符词 1,000),与 Round 2 三票独立估计(~14%)一致。
- **修正后结果**:返工匹配估计 +0.5pp(p=0.146)→ +0.92pp(p=0.019),剔除误判后 +1.19pp(p=0.002)——方向与 SDD 宣称相反。按仓库聚类后缺陷 CI [−3.8, +2.7]pp(98% 匹配对跨仓库,仓库缺陷基率 0–46%;作者 McNemar 把配对当独立)。14 种设定 × 2 处理口径(仓库 FE、仓库×月 FE、作者 FE、仓库内 PSM)无一显示保护效应:缺陷约 0 到 +1pp(可排除 >约 1pp、相对约 7–8% 的下降),返工 +0.8 到 +1.8pp 多数显著。SZZ 本身误归因 46–71%。
- **否决**:V1/V3 把 PSM 写成「精确零」;V2「匹配后返工无差异」;Round 2 按 p 值反推的 CI 作废;V5「365 天窗口」(月度 PR 数差 7 倍、半数 PR 在最后三个月、三仓采集缺口、右截尾——偏向对 SDD 有利,不翻转结论);V6 质量(H3/H4)零结果不承重(修正后 p=0.083/0.239,人工校验 n=38、ρ=0.42);V8 停止规则辩护(停止条件即「零结果稳定」);以及作为 SDD 工具效果证据(97.5% 为工单引用、样本零 SDD 工具产出)。
- **X 席**:无再分析/反驳(OpenAlex 被引 0;Spec Kit #3357 锁定转 Discussion #3373 零回复)。独立矛盾(邻近构念):Rempel & Mäder(TSE 2017,24 OSS 项目)需求→代码可追溯性越完整缺陷率越低(项目级、未控制适应症混杂;仅摘要,禁引效应量)——Hill 未引用。部分证实:Pirouzkhah(MSR 2026,80K PR/156 项目)issue 链接对合并(OR 1.091)/重开(OR 0.958)无效应,但链接与更小 diff 相关(OR 0.93),与 Hill「spec'd PR 多 1.8× 行数」相反。Herbold(EMSE)证实 `#N` 常误链至 PR。Hill 正文「Our study confirms this pattern」不成立:所引 Mund 2015 测的是系统测试用例缺陷(且结论为 spec 缺陷「to a large extent… propagate」)、Femmer 2017 测的是 smell 检测精度——Hill 的零结果在文献中是孤立的。
- **可承重写法**:「在 119 个开源仓库里,PR 是否关联工单/issue 与缺陷无可辨关联、与略多返工相关(修正分类器缺陷后更明显);这测的是『有没有工单』,不是 SDD 工具。」分级:单源已核 + 现场核验(关联);「SDD 工具是否降缺陷」未验证;「需求可追溯 ↔ 缺陷」方向存争。

## R5 spec 活性/冻结/漂移

## 对成文的总影响
1. **主张 1(先写 spec 提升产出)**:受控证据只剩「题面/规约完整度」类消融(信息量效应,非流程效应)与论文内计划消融(MapCoder −10pp);所有「SDD 流程 vs 无 spec」的直接对照都被否决或降为未验证。「SDD 更慢/更贵」方向有多个弱来源同向。
2. **主张 2(spec 保持活性)**:公开数据测不出漂移;「装了≠用了」与「多数实践者自述分叉」是仅存可承重的两条;历史前科(UML 73% 未更新、BDD 37% 共演化、Hutchinson 同步障碍)只能作类比。
3. **主张 3(spec 即源码)**:形式化一端给出最硬的反面机制证据——即便有机器验证器守住「证明 ⊢ 陈述」,「陈述 = 意图」仍大面积失守(多源证实);自然语言 spec 连验证器都没有。
4. **最大的大样本观察研究(Hill)**修正分类器缺陷后,结论从「无效应」变为「工单引用与略多返工相关」,但它测的不是 SDD。
