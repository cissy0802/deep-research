## 一、发现

### F1 主结果我能逐数复现,管线可复现性是正面信号
- 我的 PSM 重实现与作者脚本同规格:16 协变量,logit 倾向分,caliper 0.05 SD,贪心 1:1 无放回。
- H1 缺陷:17,375 对,14.66% vs 15.24%,−0.58pp,McNemar p=0.133,与 `results/propensity-score-matching.txt` 逐位一致。
- H2 返工:19,648 对,15.20% vs 14.67%,+0.53pp,p=0.142。作者是 0.1458;差异来自贪心匹配同分时的顺序,不影响任何结论。
- 作者内 LPM 也逐位复现:H1 +1.42pp [+0.50,+2.35],p=0.003;H2 +1.16pp [+0.46,+1.86],p=0.001。
- 处理变量:我重实现的分类器把作者全部 24,298 个 spec'd PR 都判为 spec'd(0 漏判),另多出 214 个,应是分类器版本差(参见 CORRECTIONS.md 的 1,015 改判)。spec_source 一致率 99.76%。

### F2 处理变量误判的根因是代码缺陷,不是正则口径问题
- `coverage.py` 第 168 行注释写的是「Strip blockquote lines ("> ...") and HTML comments before extraction」,但第 170–175 行实际只跳过以 `>` 开头的行,**没有剥离 HTML 注释**。HTML 注释只在 `_has_section_content` 里剥离。
- 论文 main.tex 第 146 行对外只声称「outside blockquoted template examples」。
- PR 正文现场核对显示,头部触发串几乎全在 `<!-- … -->` 模板注释里:
  - ray `<!-- Link related issues: "Fixes #1234" … -->`
  - litellm `<!-- e.g. "Fixes #000" -->`
  - vite / pydantic / vercel/ai / FastChat / celery 的 `#123`、`#1234`、`#4412`
  - openmrs `<!--- real example: 'TRUNK-5111: …' -->`
  - n8n `https://linear.app/n8n/issue/`
- 另有几类不在注释里的模板固定串:k8s `<kep-issue-number>`、vllm 发布说明 Google Doc、Airflow AIP 索引页、Flink JIRA 索引页、deno 的「bad title」示例 `#7123`。
- 连字符词问题:`signals.py` 第 20 行的模式 `[A-Z]{2,10}-[a-z0-9]+` 会把 CPU-only、LLM-generated、ID-based 这类词当成工单号。
- 我按作者自己声明的意图做了最小修正:(a) 剥离 HTML 注释;(b) 删除上述 4 个已核模板 URL/占位串;(c) 工单号后缀须含数字。修正后:
  - 原 spec'd 中有 **3,382 个(13.9%)翻为 unspec'd**,其中模板/注释 2,382 个、连字符词 1,000 个。
  - 主要集中在 ray 894、litellm 528、vite 262、k8s 236、vllm 142、pydantic 134。
  - 另有 803 个仍判 spec'd 但触发串换了,说明这些 PR 在占位串之外还有真实引用。Round 2 估的 2,199–2,630 是上界、1,746 是下界,本次按 PR 正文重扫后的精确量是 2,382。
  - 反向:167 个原 unspec'd 在修正后判为 spec'd。下面「clean」口径只做删除,不吸收这 167 个。

### F3 修正误判后,「匹配后返工无差异」不成立(否决依据)

| 估计(作者 SE 口径) | 原处理变量 | clean(误判→unspec'd) | 剔除误判 PR |
|---|---|---|---|
| H1 作者内 LPM(作者聚类) | +1.42 [+0.50,+2.35] p=0.003 | +1.37 [+0.39,+2.35] p=0.006 | +1.46 p=0.005 |
| H2 作者内 LPM | +1.16 [+0.46,+1.86] p=0.001 | +1.35 [+0.61,+2.10] p<0.001 | +1.42 p<0.001 |
| H1 PSM(McNemar) | −0.58 p=0.133 | −0.66 p=0.123 | −0.52 p=0.222 |
| H2 PSM(McNemar) | +0.53 p=0.142 | **+0.92 p=0.019** | **+1.19 p=0.002** |

- 非差异性误判把返工估计拉向零,作者的「matching removes the difference」(+0.5pp,p=0.146)部分来自这一稀释。
- 修正后,返工在作者自己的推断口径下**显著更多**,方向与 SDD 宣称相反。
- 缺陷估计对修正不敏感。

### F4 PSM 的推断严重低估不确定性:98% 的匹配对跨仓库
- 作者的倾向模型不含仓库,匹配也不在仓库内进行(`propensity-score-matching.py` 第 196–260 行)。复算显示 **98% 的配对两侧来自不同仓库**。
- 103 个 SZZ 仓库的 szz_buggy 基率从 0 到 46.1%(中位 8.8%,P10 1.1%,P90 24.1%,4 个仓库为 0)。跨仓库配对的结果差里混着仓库构成差。
- McNemar 又把 17,375 对当作独立。按处理组 PR 所在仓库聚类后的 95% CI:
  - H1 缺陷:iid [−1.32,+0.17] → **仓库聚类 [−3.81,+2.66]**(p_cl=0.73)
  - H2 返工:iid [−0.17,+1.23] → **[−1.69,+2.74]**
- 也就是说,作者的主估计本身只能说「看不出」:它容许约 ±25% 的相对效应。Round 2 按 p 值反推的 [−1.4,+0.2] / [−0.2,+1.2] 是 iid 口径,同样偏窄。

### F5 换成控制仓库的估计器,结论同向且更稳
都用 LPM、仓库聚类 SE;单位 pp;括号外依次为原处理变量 / clean。

| 规格 | H1 缺陷 | H2 返工 |
|---|---|---|
| 仓库 FE + 规模 | +1.69 [+0.52,+2.86] / +1.44 [+0.19,+2.68] | +1.59 [+0.63,+2.54] / +1.84 [+0.83,+2.86] |
| 仓库 FE + 16 JIT | +0.71 [−0.32,+1.74] / +0.21 [−0.70,+1.11] | +1.16 [+0.37,+1.95] / +1.37 [+0.51,+2.23] |
| 仓库×月 FE + JIT | +0.45 [−0.32,+1.22] / +0.27 [−0.59,+1.13] | +1.10 [+0.34,+1.85] / +1.27 [+0.43,+2.12] |
| 作者 FE + 规模(仓库聚类) | +1.42 [+0.37,+2.47] / +1.37 [+0.23,+2.51] | +1.16 [+0.23,+2.09] / +1.35 [+0.35,+2.35] |
| 作者 FE + JIT(作者聚类) | +0.64 [−0.40,+1.68] / +0.39 [−0.69,+1.46] | +0.89 [+0.12,+1.67] / +1.02 [+0.21,+1.84] |
| 作者 + 仓库×月 FE + JIT | +0.26 [−0.66,+1.18] / +0.30 [−0.67,+1.28] | +0.79 [−0.10,+1.69] / +0.89 [−0.05,+1.83] |
| 仓库内 PSM(仓库聚类) | +1.06 [−0.06,+2.18] / −0.02 [−1.00,+0.97] | +0.81 [−0.16,+1.78] / **+1.31 [+0.29,+2.33]** |

- 仓库内 PSM 的倾向分用 GLM 加仓库哑变量估计,匹配后 16 个协变量 |SMD| 都 ≤0.028。
- 附带一个排错记录:我第一次用 lbfgs 拟合,收敛到全 0 系数,得到 +5.9pp 的假结果,已弃用。
- 作者论文里「Controlled」那一档的仓库 FE logit 在 H1/H3 上奇异、退回了只控规模(main.tex 第 207 行有披露)。所以在本次复算之前,缺陷一侧**没有任何一个估计真正控制了仓库**。
- 汇总:14 个规格 × 2 个处理变量口径里,**没有一个估计显示规格工件带来有统计意义的缺陷或返工下降**。
  - 缺陷:控制 JIT 之后点估计在 −0.02 到 +1.06pp 之间。按仓库聚类,CI 下沿最低约 −1.0pp(仓库内 PSM)。
  - 返工:点估计全部为正(+0.8 到 +1.8pp),多数显著。
- 「没有保护效应」这一方向结论稳健,且比论文写的更强。论文 PSM 的「精确零」则不稳健。

### F6 功效 / 最小可检测效应(80% 功效,α=0.05,MDE≈2.8×SE)
- 作者 PSM,iid:SE≈0.38pp → MDE≈1.1pp(相对 15.2% 基率约 7%)。
- 作者 PSM,仓库聚类:SE≈1.65pp → MDE≈4.6pp(约 30% 相对)。
- 仓库×月 FE + JIT,仓库聚类:SE≈0.39pp → MDE≈1.1pp(约 8% 相对)。
- 结论:配合 F5 的估计器,本数据能排除大于约 1pp(约 7–8% 相对)的缺陷保护效应。只用作者的 PSM 主估计做不到这一点。论文原话「Any protective effect is smaller than this study can detect」(main.tex 第 481 行)没有量化这个边界。

### F7 时间覆盖不是均匀的「365 天面板」
- main.tex 第 110 行写「365-day lookback window per repository … spans April 2025 through early April 2026」。实际按月 PR 数从 2025-04 的 2,923 涨到 2026-03 的 19,856,约 7 倍。
- 51% 的非 bot PR 合并于 2026-01-01 之后(这段约占窗口 26%)。119 个仓库中有 60 个,半数以上 PR 落在最后三个月。
- 个别仓库有明显采集缺口:
  - oxc:2025-04 到 09 合计 8 个,2025-10 起约每月 600 个;
  - vercel/ai:2025-10 前接近 0;
  - dagster:2026-02 起骤减。
- 最后约 36 天合并的 PR 占 26%,其返工率 12.4%,低于更早期的 13.8%,30 天返工窗口和 SZZ 后续修复都被右截尾。
- 这段的 spec 率是 31.0%,高于更早期的 26.4%,所以截尾偏向让 spec'd 看起来**更少**缺陷/返工,即偏向 SDD 有利的方向。
- 剔除最后约 36 天后,H2 作者内仍为 +1.26pp(p=0.004)/ clean +1.44pp(p=0.002);仓库×月 FE 的结果见 F5。结论不变,但「一年窗口」的描述不准确。

### F8 H3/H4(质量)在 clean 样本上依旧为零,但效度太弱,不承重
- 复现作者口径:H3 p=0.164,H4 p=0.860。只取 spec'd:p=0.168 / 0.829,与 CORRECTIONS 一致。
- clean 样本(20,824 PR):H3 系数 −0.04pp/分(p=0.083),即 +10 分约 −0.4pp;H4 p=0.239。
- 量表本身的效度:人工对照只有 n=38,ρ=0.42;验收标准维度 ρ=0.17。量表测的是「形式完整性」。
- 所以 H3/H4 是一个弱零结果,不能写成「spec 质量无关紧要」。

### F9 设计层问题(作者已自承,但承重时必须带上)
- **选样与停止**:main.tex 第 118 行原文「Repositories were added while no effect was evident, and collection stopped at 119 once the null appeared stable」。作者接着论证「Optional stopping … inflates false positives rather than false negatives」。
  - 这一辩护只对「找到效应就停」成立。对「看到零结果稳定就停」不成立:后者的停止规则本身以零结果为条件,名义 p 和「稳定」都不是校准的证据。
  - 全部为事后分析,无预注册(main.tex 第 530 行)。
- **构念效度**:spec'd 97.5% 是工单/issue 引用,修正后还要再去掉约 14%;样本里 0 个 SDD 工具产出。所以本研究检验的是「PR 关联了工单」,不是 Spec Kit/Kiro 工作流。
- **结局效度**:
  - SZZ 基本版,da Costa 2017 报告误归因 46–71%;
  - 返工是「30 天内、文件重叠、标题含 fix 等词」的启发式,论文和仓库里都找不到人工精度/召回校验;
  - 还有处理与结局的机械耦合:「Fixes #N」既触发 spec'd,又让 PR 本身更可能是修复类。spec'd 在 fix=1 的 PR 中占 34.7%,fix=0 中占 25.0%,PSM 前 SMD=+0.22。PSM 和 JIT 控制了 `fix`,但残余偏差的方向无法判定。
- **利益冲突**:单作者、独立研究者,无资助声明。作者有书《The Delivery Gap》和相关指标项目,属非财务立场利益。复现包 CC-BY 公开、主动发勘误,是很强的抵消因素。
- **评审**:SEIP 轨道,有条件接收,一位审稿人建议拒稿(REVISION-PLAN 为作者自存)。
- **版本**:SSRN 版带未修正的数字和相反的头条,只能用 ESEM 正式版。

## 二、结局

**M 席评级:B(限定构念)/ D(若用作「SDD 工具是否降缺陷」的证据)**
- 限定在「大型开源 PR 是否关联工单/issue」这个构念上,评级为 B:可复现,方向稳健,但精确零不成立,构念和结局效度中等偏弱。
- 若当作 SDD 工具效果的证据,评级为 D:样本里没有处理组。

### 否决清单(不得承重)
- **V1** 「匹配后缺陷 14.7% vs 15.2%(p=0.133),匹配完全消除关联」不得作为**精确零**或「排除了保护效应」的依据。
  - 原因:98% 的配对跨仓库,McNemar 当 iid 处理;仓库聚类 CI 为 [−3.8,+2.7]pp。
  - 可以作为作者报告的点估计引用,但必须带「跨仓库匹配、未聚类」的限定。
- **V2** 「匹配后返工 +0.5pp(p=0.146)无差异/匹配消除了返工差异」否决。
  - 修正处理变量误判后为 +0.92pp(p=0.019)/ +1.19pp(p=0.002);仓库内 PSM clean 为 +1.31pp,仓库聚类 [+0.29,+2.33]。
  - 正确的说法是:返工在几乎所有规格下更多,显著性随规格变化。
- **V3** Round 2 反推的 CI「缺陷 [−1.4,+0.2]pp、返工 [−0.2,+1.2]pp,排除 >0.2pp 返工收益」作废(iid 口径)。由 F5/F6 的仓库聚类区间替代。
- **V4** 「处理变量误判约 14%」可以用,但须改写为本席的精确口径:3,382/24,298 = 13.9%,其中模板/注释占位 2,382、连字符词 1,000。
  - 根因是分类器没有按其注释剥离 HTML 注释。
  - 禁写「误判仅为噪声、不影响结论」:它已经改变了 H2 匹配估计的显著性。
- **V5** 「一年窗口(2025-04 至 2026-04)的 88,052 PR」不得暗示均匀覆盖。月度密度相差 7 倍,半数 PR 落在最后三个月,若干仓库有采集缺口。
- **V6** 「spec 质量不预测缺陷/返工(p=0.164/0.860)」不得承重。LLM 量表 n=38、ρ=0.42;clean 样本 H3 p=0.083。只能写成弱零结果。
- **V7** 「本研究表明 SDD 不降缺陷」「Spec Kit/Kiro 无效」禁写(延续 Round 2)。「作者内 +1.4pp:spec 增加缺陷」也禁写:SZZ 有机械偏差,控制 JIT 后降到 +0.3 至 +0.7pp,不显著。
- **V8** 作者的辩护「可选停止只膨胀假阳性」不得转述为方法学保证。停止规则以零结果为条件。
- **V9** 无 AI 子组的 −3.3pp(p=0.014)不得承重:6 个检验之一,未过 Bonferroni,又处在数据驱动停止之下。H5 本席没有复算。

### 可承重的最强写法
> 迄今最大的相关观察研究(Hill, ESEM 2026;119 个开源仓库、88,052 个已合并非 bot PR)里,「PR 关联了工单/issue」与更少的缺陷或返工无关。本席用作者公开数据,修正约 14% 的处理变量误判(未删除的 PR 模板占位符、连字符词),并改用仓库内比较和仓库聚类误差,共 14 种设定 × 2 种处理口径。结果没有一个估计显示保护效应:缺陷一侧在控制改动风险后约 0 到 +1pp,能排除大于约 1pp(约 7–8% 相对)的下降;返工一侧反而多 0.8–1.8pp,多数显著。但它测的是「有没有工单号」,不是 Spec Kit/Kiro 式工作流,后者在样本中根本观察不到。作者论文的「匹配后精确零」在这些修正下并不稳健:不稳健的方向是对 SDD 更不利,而不是更有利。

### 证据分级建议
- 「开源 PR 中工单/issue 引用 ≠ 更少缺陷/返工」:**单源已核 + 现场核验**(作者数据经独立复算,方向在 28 个估计中一致)。不是多源证实,因为没有独立团队、独立数据。
- 「返工反而更多(+0.8 至 +1.8pp)」:**单源已核 + 现场核验**,写成「关联」而非因果。返工启发式未经校验。
- 「能排除 >~1pp 的缺陷保护效应」:**现场核验**(本席复算)。依赖 SZZ 效度,须注明 SZZ 误归因 46–71%。
- 「SDD 工具本身是否降缺陷」:**未验证**(本研究不可检验)。
- H3/H4 质量零结果:**单源已核**,效度弱,不承重。
